# vc-x1 config file

Configure the work-repo of a dual repo system. The other repo, we call the agent-repo, is
also a markdown configuration file typically named .vc-config.md.

The code blocks in these config files are in toml format and these blocks are logically
concatenated in the order written here and those become the information used for configuring
the system. The [vc-config.md](vc-config.md) contains the documentation for the
various toml tables used for configuration and it is also used during compilation to define
the valid contents of this file.

The file [vc-config-model.md](vc-config-model.md) is the model: every table and key a workspace
config may carry, each with its default or a typical value. It is generated from the schema, so it
cannot fall behind the keys the binary knows.

The two repos
- work [[1]]
- agent [[2]]
```toml
[repos]
work = "."
agent = ".agent-session"
```

The agent-repo's name on its remote, which clone and sync need when there is no agent-repo yet to
ask
- agent-repo [[9]]
```toml
[remote]
agent-repo = "vc-x1.agent-session"
```

The agent-file family this repo belongs to: its member name and the sibling repos it answers to
- member [[3]]
- template [[4]]
- messages [[5]]
```toml
[family]
member = "vc-x1"
template = "../vc-x1-template/work"
messages = "../vc-x1-messages"
```

The validation commands, each element one invocation, run in order by `vc-x1 validate`
- full [[6]]
- fast [[7]], `cargo test --bins` alone, the schema's example, wink's call 2026-10-20: the full
  list with plain `cargo test` measured the same 8 s as full, since the fourteen `dr1_*` fixture
  tests cost nothing once the fixture is built, so the only fast worth having skips fmt, clippy,
  the integration tests, and the install. Its trial of 2026-09-21 found a rung's failures in what
  it skips, so a rung's review still runs full
- full ends with the dev install, `[install] dev` below, so every full validation leaves the
  rung's binary under `tmp/dev` and the `vc-x1` on the PATH is never replaced by a cycle's build
```toml
[validate]
full = [
  "cargo fmt",
  "cargo clippy --all-targets -- -D warnings",
  "cargo test -- --include-ignored",
  "cargo install --path . --locked --root tmp/dev",
]
fast = ["cargo test --bins"]
```

The install commands, each element one invocation, run in order
- release [[10]], the promotion, run by `vc-x1 install` from `main` at a cycle's Land
- dev [[11]], the dev install, run by `vc-x1 install --dev` and as full's last entry, under
  `tmp/dev` so the package keeps its name and nothing on the PATH is replaced
- dev-bin [[12]], the binary the dev install leaves, run by `vc-x1 run-dev`
```toml
[install]
release = ["cargo install --path . --locked"]
dev = ["cargo install --path . --locked --root tmp/dev"]
dev-bin = "tmp/dev/bin/vc-x1"
```

The acceptance-test fixtures, one dual workspace per name under the directory, inside the
workspace and gitignored, so a fresh clone builds or fetches its own there and the committed config
names no path on one machine
- fixtures [[8]]
```toml
[test]
fixtures = ".fixtures"
```
